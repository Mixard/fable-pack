# solution-hunter — дизайн скила нон-стоп поиска решений

Дата: 2026-07-25. Статус: утверждён пользователем, доработан по критическому ревью (5 линз: враждебный скептик, pre-mortem, противоречия механике, аудит допущений, свежий взгляд). Ждёт план реализации.

## Задача

Скил, превращающий сессию Claude Code в непрерывный исследовательский цикл: пользователь задаёт задачу («стратегия иксов к депозиту $200»), процесс через субагентов генерирует идеи, комбинирует их, адверсариально перепроверяет и не останавливается по собственной инициативе — только по команде пользователя или по правилам автопаузы.

## Решение (выбранный подход)

Скил-оркестратор в плагине `fable-workflows` на базе механизма `/loop` (dynamic mode, ScheduleWakeup): пробуждение → раунд → обновление файлового состояния → следующее пробуждение. Содержательная работа (генерация, комбинация, опровержение) — в субагентах; синтез и запись состояния — единственная фаза в основной сессии; состояние — только в файлах.

Альтернативы:

- **Workflow как внешний цикл** — отклонён: конечен, нет вмешательства пользователя между раундами. Но Workflow *внутри* раунда (детерминированный pipeline фаз) — допустимая оптимизация реализации: снижает риск «пропущенной фазы» на позднем раунде.
- **Cron / облачный routine (`/schedule`)** — отклонён решением пользователя (выбран режим «пока открыта сессия»: контроль и стоимость). Отличие честно фиксируем: routine переживает закрытие сессии, /loop — нет; cron-надстройка возможна позже (этап 2).
- **Субагент-оркестратор** — отклонён: субагент не умеет планировать пробуждения и жить бесконечно.
- **Композиция существующих скилов** — частично принята: правила критиков берутся из critical-review и *инлайнятся в промпты при сборке скила* (с пометкой источника — обновления critical-review переносятся осознанно, а не дрейфуют); генерация — паттерн dispatching-parallel-agents; застревание — протокол getting-unstuck.

## 0. Предусловия

- Каталог состояния — `research/<slug>/` **внутри рабочей директории проекта** (не `~/`), чтобы записи не упирались в permission prompts.
- На интейке скил проверяет разрешения: запись в `research/**`, WebSearch/WebFetch для субагентов. Нет разрешений → предложить добавить в settings.json до старта; иначе автономный цикл повиснет на промпте, когда пользователя нет.

## 1. Запуск и интейк

`/solution-hunter <задача>`. В `BRIEF.md` фиксируются:

- цель;
- критерий «достаточно близко» — измеримый **и проверяемый доступными инструментами**: для каждого типа evidence указан способ проверки, которым реально владеет субагент (WebSearch, расчёт в Bash, данные пользователя). Если критерий проверить нечем — скил говорит это прямо и предлагает: прокси-критерий ЛИБО явный режим «гипотезы без верификации» (пометка в BRIEF и в каждом отчёте);
- ограничения задачи (бюджет, риск, время);
- **бюджет самого поиска**: лимит раундов в сутки (default 24), суммарный лимит до явного «продолжить?» (default 100), автопауза после 24 ч без сообщений пользователя;
- если пользователь не ответил на уточняющий вопрос — скил ставит разумный дефолт с пометкой `assumed`; каждый отчёт о кандидате повторяет assumed-допущения.

## 2. Файловое состояние

`research/<slug>/`:

| Файл | Содержимое |
|---|---|
| `BRIEF.md` | задача, критерии, ограничения, бюджет поиска; корректировки пользователя — append-only |
| `STATE.md` | якорь процедуры: номер раунда, текущая фаза, время следующего пробуждения, счётчики (сухие раунды, раунды без ответа пользователя). Перечитывается первым действием каждого пробуждения |
| `LEDGER.md` | компактный индекс: одна строка на идею — id, каноническая формулировка, статус, счёт |
| `ideas/<id>.md` | полная карточка идеи: гипотеза, линза-источник, evidence, вердикты |
| `CANDIDATES.md` | идеи со статусом candidate |
| `ROUNDS.md` | журнал раундов: дельты, использованные линзы, новые факты из вердиктов |
| `STATUS.md` | дашборд на полстраницы: топ-кандидаты, счётчики, расход, открытые вопросы. Перезаписывается каждый раунд — вернувшийся пользователь входит в курс за минуту |

Статусы идей (единый словарь с вердиктами критиков): `raw → combined → confirmed | refuted | inconclusive`; `confirmed` + проходит критерий BRIEF → `candidate`. `inconclusive` хранится с ценой проверки. Убитые идеи остаются в индексе навсегда (для дедупа). В файлы состояния пишет **только оркестратор**, атомарно, в конце фазы — субагенты возвращают текст, не трогают файлы.

## 3. Раунд (средний профиль: ~8–12 субагентов, раз в 20–30 мин)

Жёсткий порядок пробуждения:

0. Перечитать `STATE.md` + `BRIEF.md` + новые сообщения пользователя — **до запуска субагентов** («стоп» → финал; корректировки → в BRIEF).
1. Запланировать страховочное следующее пробуждение **первым действием** (синтез может его перенести, но раунд никогда не идёт с незапланированным следующим пробуждением).
2. Фазы:
   - **Генерация** — 3–4 субагента на `sonnet`, линзы ротируются из пула (аналогии из чужих доменов, инверсия, веб-разведка, contrarian, декомпозиция). На вход — сжатый список «не повторяй»: канонические строки существующих/убитых идей с причиной смерти, *не* полные карточки (меньше якорения на чужих формулировках).
   - **Комбинация** — один субагент скрещивает топ-идеи индекса.
   - **Опровержение** — 3 критика-субагента с наследованием модели сессии, линзы: *враждебный скептик* / *pre-mortem* / *противоречие с данными LEDGER*. Критик **сам исполняет** дешёвые проверки (WebSearch, расчёт) в таймбоксе; дорогая проверка → `INCONCLUSIVE` с ценой. Формат вердикта:

     ```
     Идея: <id и гипотеза>
     Тест: <конкретная проверка, исполненная критиком> (таймбокс)
     Вердикт: CONFIRMED | REFUTED | INCONCLUSIVE
     Новый факт: <что узнали, даже если идея убита>
     ```

     Ранжирование проверок — по цене теста, не по комфорту. Красные флаги (в духе critical-review, текст инлайнится в промпт): не смягчать вердикт своим идеям; идея без конкретного теста — возврат генератору на конкретизацию.
   - **Синтез** — оркестратор (основная сессия): обновляет файлы, дельту пишет в ROUNDS.md, «новые факты» — генераторам следующего раунда; чат — только события (§5).

**Контракт промпта каждого субагента** (обязателен — субагент стартует с чистым контекстом и не видит ни сессию, ни LEDGER, ни другие скилы): абсолютный путь `research/<slug>/` + явная инструкция «сначала прочитай BRIEF.md, LEDGER.md, ROUNDS.md» + правила вердикта и красные флаги инлайном.

## 4. Анти-застревание

- **Сухой раунд** = ни одной новой (не перефраз) идеи, ЛИБО ни одного вердикта CONFIRMED/REFUTED (одни inconclusive — тоже сухо).
- 2 сухих подряд → принудительная смена линз + протокол getting-unstuck (какое скрытое допущение сужает поиск).
- 4 сухих → переформулировка задачи + вопрос пользователю. Вопрос **не** останавливает планирование пробуждений: цикл продолжается или уходит в автопаузу по правилам §5.
- Дедуп: `haiku` по компактному индексу LEDGER (канонические строки, не полный файл); при индексе > 200 идей дедуп эскалируется на `sonnet`.

## 5. Автономный режим и управление

- Команды пользователя обрабатываются в начале следующего пробуждения; сообщение между пробуждениями ждёт до 30 мин — принятое ограничение среды (сообщения приходят только между ходами).
- «Стоп» → `ScheduleWakeup(stop: true)` — гасит запланированные пробуждения (подтверждено схемой инструмента: «no further wakeups fire») + финальный сводный отчёт по LEDGER.
- **Автопауза** (пауза ≠ стоп, отчёт не финализируется): 24 ч без сообщений пользователя, ИЛИ достигнут дневной лимит раундов, ИЛИ суммарный лимит. Возобновление — первым сообщением пользователя.
- Чат — **только события**: новый кандидат, эскалация после сухих раундов, автопауза, короткая строка прогресса раз в ~10 раундов. Журнал — ROUNDS.md, положение дел — STATUS.md; чат не является логом.
- Опция (этап 2, не MVP): пуш о кандидате/автопаузе в Telegram — у пользователя есть инфраструктура; отдельное решение с отдельной ценой.

## 6. Восстановление

- Wakeup-prompt самодостаточен: slug, путь `research/<slug>/`, инструкция «перечитай SKILL.md solution-hunter и STATE.md». Так цикл переживает сжатие контекста: процедура заякорена в файлах, не в памяти сессии.
- `/solution-hunter resume <slug>` — восстановление цикла из файлов после смерти сессии или упавшего раунда.

## 7. Модели и бюджет

- Генераторы — `sonnet`; механика (дедуп, черновая сборка файлов) — `haiku` с эскалацией по порогу; критики — субагенты с наследованием модели сессии; синтез — основная сессия. Правило: субагент не наследует модель оркестратора там, где хватает уровня ниже.
- Экономика в спеке не посчитана — это вход первого теста, не допущение: до реализации замерить стоимость и wall-clock одного полного раунда на демо-задаче. Раунд дольше ~15 мин или дороже согласованного порога → профиль/темп пересматриваются.

## 8. Этапность

- **Этап 0 (MVP)** — режим «раунд по запросу»: пользователь командой запускает один раунд, читает STATUS.md. На нём калибруются: стоимость раунда; качество генераторов на sonnet; доля реальных вердиктов у WebSearch-проверки (если < 40% — пересмотр evidence-стандарта); дедуп на перефразах; конвергенция трёх критиков (если > 80% вердиктов совпадают — схлопнуть в одного критика с тремя линзами, втрое дешевле).
- **Этап 1** — автономный цикл на /loop со всем из §3–6.
- **Этап 2 (опции)** — Telegram-пуши, cron-надстройка для 24/7.

## 9. Упаковка

- Скил `solution-hunter` в `plugins/fable-workflows/skills/`, на английском (как остальные), русские триггеры в description: «ищи варианты нон-стоп», «перебирай идеи», «не останавливайся пока не найдёшь».
- Bump версии плагина + plugin update после мержа.
- Границы с соседями: critical-review — разовая проверка существующих материалов; getting-unstuck — ломка объявленного тупика; solution-hunter — непрерывный поиск нового, использующий оба как встроенные фазы.

## Тестирование

- **Длинный прогон**: 10+ раундов на задаче с известным ответом — кандидат найден и помечен; чек-листом проверено, что фазы 0–2 исполнены в каждом раунде без пропусков.
- **Дедуп**: в LEDGER refuted-идея + её перефраз → фильтр ловит обе (тестируется фильтр после генерации, не сами генераторы).
- **Стоп**: «стоп», отправленный между пробуждениями, обработан в начале следующего пробуждения: ни одного нового субагента, финальный отчёт, пробуждения погашены.
- **Выживание**: искусственно уронить раунд посреди фаз → страховочное пробуждение наступает, STATE.md позволяет продолжить без потери счётчиков.
- **Компакция**: форсировать /compact между раундами → раунд N+1 начинается с чтения STATE.md, счётчики и правила не обнулились.
- **Задача без находимого ответа** → эскалация сухих раундов срабатывает на калиброванных порогах, цикл уходит в getting-unstuck, а не жжёт токены на перефразах.
- **Интейк с непроверяемым критерием** → скил явно предлагает прокси-критерий или режим «без верификации», не стартует молча.
